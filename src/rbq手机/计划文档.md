# 沉浸式手机应用模拟器 - AI开发执行计划

## 项目概述

**项目名称**：沉浸式手机应用模拟器（暂定名：Phone Simulator）

**项目类型**：脚本项目（仅index.ts，后台运行）

**核心目标**：
1. 为SillyTavern创建一个沉浸式手机UI，在聊天消息中呈现手机APP的完整界面体验
2. 支持多种消息类型（文本、图片、表情、动态等）的渲染
3. 支持UI定制（尺寸、颜色、样式）
4. 持久化存储玩家对话、动态等数据

### 任务1.2：设计核心数据结构

#### 消息数据结构 (参考柏柏的parseQQmsgtype概念)

```typescript
interface Message {
  id: string;                      // 唯一标识
  type: 'text' | 'image' | 'emoji' | 'music' | 'system';
  content: string;                 // 消息内容
  sender: string;                  // 发送者名称
  senderAvatar?: string;           // 发送者头像URL
  timestamp: string;               // 时间戳 HH:MM
  reactions?: string[];            // 表情反应（点赞等）
}

interface Chat {
  id: string;                      // 聊天唯一标识
  otherName: string;               // 对方名称
  otherAvatar?: string;            // 对方头像
  messages: Message[];             // 聊天消息列表
  lastMessage?: Message;           // 最后一条消息
  unread: number;                  // 未读数
  lastTime: string;                // 最后交互时间
}

interface Post {
  id: string;                      // 动态唯一标识
  authorName: string;              // 发布者名称
  authorAvatar?: string;           // 发布者头像
  content: string;                 // 动态内容
  images?: string[];               // 动态中的图片
  timestamp: string;               // 发布时间
  likes: number;                   // 点赞数
  comments: number;                // 评论数
}

interface PhoneState {
  // UI状态
  isVisible: boolean;              // 手机是否显示
  position: { x: number; y: number }; // 拖动位置
  size: { width: number; height: number }; // 手机尺寸

  // 主题/外观
  theme: {
    borderColor: string;           // 边框色
    backgroundColor: string;       // 背景色
    bubbleColor: { mine: string; other: string }; // 气泡色
    textColor: string;             // 字体色
  };

  // 数据
  chats: Map<string, Chat>;        // 所有聊天
  posts: Post[];                   // 所有动态
  currentChatId?: string;          // 当前聊天ID
  currentPage: 'chat' | 'home';    // 当前页面
}
```

## 第五阶段：数据持久化

### 任务5.1：选择数据存储方案

**方案A：使用MVU框架**（参考`src/咩咩手机界面/mvu介绍/`）
- 在消息楼层变量中存储chat和post数据
- AI可以通过MVU指令更新数据
- 适合动态角色状态系统

**方案B：使用世界书配置**（参考`src/柏柏手机界面/worldbook/`）
- 全局配置（表情包、基本设置）存在世界书
- 聊天/动态数据存在酒馆变量或脚本变量
- 适合角色卡创建者易于配置

**推荐**：方案B + 简化版MVU
- 世界书存全局配置
- 脚本变量存聊天/动态数据
- 简单可靠

### 任务5.2：实现数据加载逻辑

**实现内容**：
1. 初始化时从世界书读取配置
   - 主题颜色配置
   - 表情包列表
   - 其他基本设置

2. 初始化时从酒馆变量读取已有数据
   - 使用 `getVariables({ type: 'script', script_id: getScriptId() })`
   - 加载chats和posts数据

3. 初始化时从聊天记录读取历史消息
   - 使用 `getChatMessages()`
   - 从已有消息中提取phone格式内容
   - 重建chat和post数据结构

### 任务5.3：实现数据保存逻辑

**实现内容**：
1. 消息更新时自动保存
   - watch phone-state的chats和posts
   - 序列化为JSON
   - 使用 `replaceVariables()` 保存到酒馆变量

2. UI状态保存
   - 位置、尺寸等存到IndexedDB（参考咩咩项目）
   - 主题设置存到酒馆变量或IndexedDB

### 任务5.4：实现数据同步机制

**实现内容**：
1. 当新消息到达时，自动解析并更新phone-state
2. 当用户切换角色卡时，重新加载该角色的phone数据
3. 当用户刷新页面时，重新加载已保存的phone数据

## 注意事项

1. **脚本 vs 前端界面**：本项目是脚本（仅index.ts），在后台运行。使用Vue来组织代码，最终挂载到主页面。

2. **样式传输**：由于运行在iframe中，需要使用teleport_style函数将iframe的样式传到主页面的<head>中。

3. **事件监听**：使用 `$(() => {})` 来在加载时执行，使用 `$(window).on('pagehide')` 在卸载时执行。

4. **数据同步**：消息可能来自两个源：(1) 已有的酒馆聊天记录（包含phone格式）；(2) 新的AI输出。两者都要处理。

5. **TypeScript**：确保代码中有完整的类型定义，利用zod进行数据验证。

6. **响应式**：使用CSS变量和媒体查询使UI适应不同尺寸。

7. **性能**：大量消息时考虑虚拟滚动、消息分页加载等优化。
