变量更新规则:
  手机数据:
    当前时间:
      type: string
      range: 格式化的日期时间字符串，如 "YYYY-MM-DD HH:MM:SS"
      check:
        - 每次对话或互动后根据故事推进更新
        - 新的一天开始时更新到对应日期
        - 重要事件后根据情节需要调整
    用户:
      空间动态:
        description: 参考联系人动态结构和规则
    联系人:
      type: object
      range: 动态扩展的对象集合
      check:
        - 使用{{联系人名称}}作为对象KEY

      联系人对象(对应{{联系人名称}}的值):
        昵称:
          type: string
          range: 字符串，角色之间的称呼
          check:
            - 关系变化时可能更新昵称
            - 角色主动要求修改时更新
            - 一般保持相对稳定

        聊天记录:
          type: object
          range: 按格式化时间字符串索引的消息对象集合，KEY为{{发送消息的时间}}
          check:
            - 每次对话时添加新的时间消息条目
            - KEY值为当前对话时间的格式化时间字符串
          description: |
            此时间是消息发送的具体时间点，必须严格参考并略微早于当前的剧情时间（手机数据.当前时间），以确保消息的发生时间与故事的整体时间线保持一致。
            例如，如果当前剧情时间是 "2025-01-23 09:01:00"，那么发送的消息时间应该是 "2025-01-23 09:01:00" 之前的一个合理时间。

          消息对象(对应{{发送消息的时间}}的值):
            is_user:
              type: boolean
              range: 布尔值
              check:
                - 用户发送的消息设为true
                - 角色发送的消息设为false

            message:
              type: string
              range: 字符串，消息内容
              check:
                - 包含实际对话文本内容
                - 保持角色语言风格一致性
                - 根据情境和角色性格编写内容

        空间动态:
          type: object
          range: 动态扩展的对象集合，KEY为格式化时间字符串
          check:
            - 角色发布新动态时添加新的时间KEY
            - KEY格式为 "YYYY-MM-DD HH:MM:SS"
            - 每个KEY对应一条动态内容

          动态对象(对应{{发送动态的时间}}KEY的值):
            内容:
              type: string
              range: 文本内容，描述动态信息
              check:
                - 根据角色当前状态和活动编写内容
                - 体现角色性格和当前关注点
                - 保持语言风格一致性

            评论:
              type: object
              range: 动态扩展的对象集合，KEY为递增数字字符串（"1", "2", "3"...）
              check:
                - 其他角色或用户评论时添加新的数字KEY
                - 按照评论顺序递增分配KEY
                - 使用字符串格式的数字作为KEY
              description: |
                评论KEY使用简单递增的数字字符串，从"1"开始。
                添加新评论时，使用下一个可用的数字。
                删除评论时，直接删除对应的数字KEY即可。

              评论对象(对应{{评论ID}}KEY的值):
                ID:
                  type: string
                  range: 评论者标识符，使用{{评论者ID}}
                  check:
                    - 使用{{评论者ID}}作为标识
                    - 用户评论时使用{{user}}
                    - 角色评论时使用角色名称

                发言内容:
                  type: string
                  range: 评论文本内容
                  check:
                    - 根据评论者角色特点编写内容
                    - 模拟真实的空间互动，所有人可讨论、评论、吐槽、相互回复
                    - 保持角色语言风格一致性
                    - 回复其他人使用"@{被回复者ID}：${回复内容}"
